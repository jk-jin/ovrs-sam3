# ReCA-SAM3 论文绘图规范

本文件是本项目后续新绘图和重绘的统一视觉规范。规范说明用中文；正式图内文字、子图名称、图例和论文图注用英文。

视觉基准是用户确认并完成间距修正的 [overview.drawio](src/overview.drawio) 与 [overview.pdf](overview.pdf)，对应提交 [7d43658](https://github.com/jk-jin/ovrs-sam3/commit/7d436588d9fd735fcde9b46c2acc2bbb7cf941b1)。参考图用于确定绘制方式，具体模型结构始终以源码和有效配置为准。旧图尚未统一的字体与颜色不构成新规范；本文件不要求在一次文档更新中自动重绘所有旧图。

## 1. 视觉目标与适用范围

读者首先看清模型的几个阶段，再看清主要特征流和引导关系，最后根据局部图理解算子。总体图应同时具有真实遥感任务的直观感、结构分区的秩序感和可编辑的矢量细节。

采用以下固定原则：

- 整体白底，阶段标题放在白色留白中；浅色背景只用于内部功能组。
- 总览用阶段组织，模块用图标和简短名称组织，张量用叠片、网格、向量条等形状表达。
- 遥感图像、响应热力图与分割图承担任务展示；图标、叠片承担结构说明，二者不能互相冒充。
- 主推理路径最突出；语义／空间引导次之；蒸馏监督位于低强调的训练区域。
- 留白、对齐、统一的符号含义优先于装饰；不把全部内容都变成相同的“矩形框＋大段文字”。

总体框架、模块详图、机制示意和定性对比均遵循这些原则，但不强求所有图都有三个阶段。一个局部模块只需展示其自身关系。

## 2. 总体布局与信息层级

### 2.1 总体图的三个阶段

当前 overview 固定为从左到右的三个白底板块：

| 板块 | 英文标题 | 需要让读者看清的内容 |
| --- | --- | --- |
| (a) | Class-conditioned Feature Generation | 图像／文本输入、SAM 3 条件特征、RemoteCLIP 图文匹配和语义引导的生成 |
| (b) | RemoteCLIP-guided Feature Aggregation | 完整聚合块、类间交互、共享三尺度窗口、引导与特征值的不同作用 |
| (c) | Feature Fusion and Segmentation | 聚合特征、原始跳连、SDF、冻结解码器和输出示例 |

板块 (b) 是当前方法重点，应分配最大的有效宽度。图下方单独放置横向训练蒸馏栏，图例放在剩余空白区域。训练栏不能挤占主结构的主要展示空间。

### 2.2 框与标题的层级

| 层级 | 绘制方式 | 标题位置 |
| --- | --- | --- |
| 整张图 | 白底，不额外包一圈总边框，不放重复论文图题的大标题 | 总图题由 LaTeX caption 提供 |
| 阶段板块 | 细灰色虚线、较大圆角、白色填充 | 板块内部顶部的白色留白 |
| 完整聚合块 | 细浅紫／灰紫实线，白色或近白填充 | 块顶部留白，标注 Block 1 / Block 2 |
| 功能组 | 小圆角、浅色填充、细边框 | 组内顶部，正文图形位于标题下方 |
| 算子与标量 | 更小的圆角框或符号节点 | 短名称居中，保留内边距 |

阶段边界用于组织内容，不代表一个可学习模块。不能把整个阶段涂成大面积彩色底，再把标题压在彩色底上。也不能让一个功能框承担阶段、算子、张量三种含义。

### 2.3 总览与详图的分工

总体图保留输入、输出、主要信息流和方法贡献。投影、归一化、窗口划分等细节在确有必要时放入聚合详图。简单 SDF 在总览中用小模块和明确输入即可，不恢复独立 SDF 结构图。

### 2.4 当前 Figure 3 的范围

Figure 3 专门解释 RemoteCLIP 如何指导一个 aggregation block，采用连续单图，不分栏、不设 (a)/(b)/(c) 子图。主蓝色特征流依次经过类间和类内注意力及两次残差；紫色语义引导准备过程置于块边界外，标明每次前向生成一次并由各块复用。

上方保留 64 个独立模板文本向量、64 张相似度图和紧凑的 score embedding 卷积编码，不能把模板先平均为一个向量。最终稠密图像特征既计算相似度，也直接参与卷积融合。注意力内部重点展示独立归一化、Q/K 拼接和仅来自条件特征的 V；绿色 FPN 只进入类内 Q/K。

三尺度窗口、重复块、完整编码／解码和训练损失的结构优先在 Figure 2 表达。Figure 3 的尺度融合只保留小型摘要节点，图注解释省略的对齐、权重和归一化，不因简化改变实际算法。更改当前图示范围时同步维护本节、图目录 README 与图注，避免再次扩展成重复的多栏总览。

## 3. 配色规范

使用低饱和度浅色填充、略深的同色系轮廓，以及深灰文字。以下是当前 overview 的项目调色板，不是期刊强制色值。

| 对象 | 填充色 | 轮廓／连线色 | 说明 |
| --- | --- | --- | --- |
| 画布、阶段背景 | `#FFFFFF` | 阶段边界 `#929BA4` | 保持白色留白 |
| 常规文字 | 无 | `#283039` | 避免用浅色承载关键说明 |
| 普通小框 | `#FFFFFF` | `#B9C3CC` | 中性的辅助对象 |
| SAM 3 功能底板 | `#EFF5FA` | 无或浅灰 | 仅在需要分组时使用 |
| SAM 3 编码器 | `#E8F2FA` | `#709DBD` | 解码器可用相近的 `#EAF3FA` |
| 条件特征叠片 | `#DCE8F2` | `#92B3CF` | 蓝色特征流 |
| RemoteCLIP 功能底板 | `#FFF8E9` | 无或浅灰 | 不使用高饱和度黄色大底 |
| RemoteCLIP 编码器 | `#FFF1D5` | `#CDB683` | 火焰图标用柔和琥珀色 |
| 语义引导功能底板 | `#F5F1F9` | 无或浅灰 | 与主特征区别 |
| 语义叠片与 Q/K 端口 | `#EEE8F5` / `#F5F0FB` | `#B6A5CB` / `#B9A9CA` | 引导连线 `#A295B9` |
| 类间注意力功能框 | `#FCF2EA` | `#DCC1A8` | 浅桃色 |
| 多尺度窗口注意力 | `#F0F8F3` | `#B1CFC0` | 浅绿色 |
| FPN 空间引导 | `#F3F9F6` | `#B4CDBF` | 引导连线 `#7FAE9B` |
| SDF／尺度融合节点 | `#FFF6DD` / `#FFF3D9` | `#D0BA8D` / `#CFB88D` | 小面积浅奶油色 |
| 训练蒸馏栏 | `#FAFBFC` | `#A6ADB4` | 文字 `#66717B`，连线 `#8D969E` |
| 图片占位 | `#F9FAFB` | `#9FA7AE` | 棋盘格辅助色 `#EEF0F2` |

补充规则：

- 同一语义对象跨图保持同色；不要因为换了子图就把语义引导由紫色改成蓝色。
- 不同类别的示例提示卡片可以使用浅蓝、浅米、浅绿，但不能与“冻结／训练状态”混为一种编码。
- 蒸馏栏不用红色、高饱和橙色、粗重轮廓或强阴影强调。灰色仅表示视觉层级，不能降低文字可读性。
- 真实影像保持自然颜色；真实热力图和类别掩码使用适合其数值／类别含义的色表。掩码中的某个类别可以是红色，这与把整个训练分支涂红是两回事。
- 不给网络模块添加拟物材质、大面积渐变或厚重投影。层次主要由空间、轮廓和少量浅色建立。

## 4. 留白、尺寸与对齐

### 4.1 基准单位

当前 overview 的画布为 **2000×1000**。下表数字均是该画布上的几何单位，不是最终论文中的 pt、毫米或屏幕像素。画布等比例缩放时，间距、线宽和图标应一起缩放。

| 项目 | 参考要求 |
| --- | --- |
| 普通功能卡片的内容内边距 | 通常 15–20；边框到子图形的轮廓应能看见明确空隙 |
| 小型标量／端口卡片的内边距 | 通常 8–12；文字、子标签不能贴着卡片线 |
| 输出图片到阶段外边框 | 至少约 20 |
| 功能框到完整 Block 外框 | 通常至少 20；连接器进出点不按内容处理 |
| 相邻独立卡片的空隙 | 建议 12–20，拥挤时优先增加可用空间 |
| 标题与第一排内容 | 保留独立空隙，建议至少 10–15 |
| 最后一排内容／说明与底边 | 单独检查，不能被标题占用的空间抵消 |
| 普通框线 | 约 1.5 |
| 主路径连线 | 约 2.0–2.2 |
| 引导／辅助连线 | 约 1.6–1.9 |
| 功能框圆角半径 | 约 10–18；阶段和 Block 可约 20–24 |

这些数值是绘制起点。验收看实际轮廓和文字，而不是只看对象的包围盒是否“在框内”。圆角处也须留白。若阴影、透明片或字形伸出包围盒，应按可见内容检查。

### 4.2 必须防止的贴边情况

重点检查编码器卡片的右侧、语义引导叠片与底板边缘、三尺度说明的底部、权重卡片的子标签，以及最终输出图片与阶段右边界。`Shared within each block` 要完整位于窗口功能框内部，其底部与框线之间必须有空隙。

标题、图形、连线应分别预留空间。空间不足时，依次采用缩短冗余措辞、显式分行、调整布局、增加图高、拆出详图；不要连续缩小字体来维持原有拥挤布局。

有意叠放的提示卡片、特征切片和前后 Block 可以互相遮挡，但不能用“叠放效果”解释内容贴着其所属功能框边缘的问题。

## 5. 字体、标签与符号

- 新绘架构图默认采用 **Liberation Sans**，常规和粗体两种字重即可。旧图保留的 Liberation Serif 只表示尚未迁移；以后重绘时统一，不能在同一张图中随意混用。
- 阶段标题最醒目，Block 标题次之，功能标题再次之，张量说明和辅助说明更小。不要把每个小标签都加粗。
- 当前 2000 宽画布可参考：阶段标题约 30–31，Block 标题约 28，功能标题约 22–26，主要对象文字约 20–23，辅助文字约 17–20。小标量标签允许更小，但最终必须在论文尺寸下复查。
- 画布字号不能直接当作论文字号。按实际单栏／跨栏宽度查看导出的 PDF，确保标签无需放大即可辨认；过小的非必要细节移至图注或详图。
- 手动设置合理换行，尽量不超过两至三行。避免依赖 draw.io 自动换行，使编辑器与 PDF 出现不同布局。
- 用 `SAM 3`、`RemoteCLIP`、`Block 1`、`Block 2`、`Cross-class attention`、`Multiscale window attention`、`Q/K guidance` 等一致名称。
- 图注解释所有缩写和操作符；引入数学符号时说明含义、输入来源和作用对象，不为装饰添加公式。

| 标记 | 本项目含义 | 绘图约束 |
| --- | --- | --- |
| Q / K / V | 注意力的查询、键、值 | 明确哪些特征参与 Q/K，哪些提供 V |
| 圆形 `+` | 残差相加 | 画出更新量与原特征的两路输入 |
| `Σ` | 对齐后的三尺度特征按权重求和 | 不能误画成拼接或简单无权平均 |
| w1 / w2 / w3 | 三尺度 Softmax 后的权重，依次对应 36、24、12 尺度 | 当前版本为每块学习的三个标量，不是逐像素图像门控 |
| LN | LayerNorm，层归一化 | 位置按实际实现，当前在完整块堆叠后 |
| SDF | Semantic–Detail Fusion，语义—细节融合 | 当前总览只用紧凑模块表示 |
| 雪花 | 冻结参数的模块 | 配合图例，不能推断该模块之后所有计算都无梯度 |
| 火焰 | 被微调的 RemoteCLIP 注意力参数 | 不表示编码器全部参数都训练 |

## 6. 图形和图标的统一用法

| 对象 | 默认表示 | 应避免的问题 |
| --- | --- | --- |
| 编码器／解码器 | 浅色梯形或轻微收缩的网络块，配简短名称 | 整个网络画成长段说明书 |
| 冻结／微调状态 | 原生矢量雪花／火焰和图例 | 使用依赖系统彩色字体的 emoji |
| 网络内部示意 | 少量节点和连接线 | 画过多神经元抢占主体空间 |
| 稠密特征 | 半透明矩形切片叠放，少量网格 | 误称为已经提取的真实热力图 |
| 类内空间网格 | 正方形网格，实际窗口数可辨认 | 用模糊小方块代替窗口关系 |
| 文本提示 | 错位卡片，写 building / road / vegetation 等示例 | 让人误以为模型只支持这几个类别 |
| FPN | 三层或少量分层梯形的金字塔 | 无依据地把示意层数写成真实输出级数 |
| 图像／响应 | 矩形图片槽，必要时并列或局部放大 | 随意裁切导致样本不一致 |
| 缓存／数据库 | 只有确实存在该机制时才使用存储图标 | 为了美观添加不存在的模块 |

原生图形优先，允许小型自定义矢量 stencil，但必须自包含并能在 draw.io 打开。真实图像可以是嵌入的位图，连接器、标题、图标、叠片和窗口仍保持独立可编辑。禁止把整张生成预览作为一张 PNG 塞进 draw.io 充当源图。

## 7. 特征叠片和类间注意力的绘法

### 7.1 竖直特征叠片

普通特征可用三至四张矩形切片，后方切片向右上方露出。当前示例每层水平错位约 7、垂直错位约 6。层与层的轮廓应清楚，但不能透明到所有网格糊成一团。

叠片数量只是张量示意，不是实际通道数、注意力头数或提示数。真实维度用文字说明，不让读者靠数切片猜维度。

### 7.2 类间注意力中的平放透视切片

每个示例提示对应一组平放的特征平面：

1. 用同一方向的平行四边形表示空间平面，右侧向远处延伸，全部提示保持相同透视。
2. 当前参考为四层，每层沿屏幕竖直方向错开约 6；平面水平位置保持一致。先画后方／底层，再画前景／顶层。
3. 不要沿平行四边形的斜边方向平移全部层。那会让相邻轮廓共线，看上去只有一张细斜片。
4. 前景平面可加少量透视网格；在相同局部位置标出浅橙小方块，表示跨提示关注同一空间位置。
5. 将 building、road、vegetation 等提示按行对齐，连接同位置标记，旁边用少量节点组成提示交互示意。
6. 示意图表达沿提示轴交互，不把类间注意力画成不同像素位置之间的空间滑动。同类别的同义提示也可参与该提示轴，不能把提示数等同于语义类别数。

小方块、连线和切片必须仍在类间功能框内部留有余量。网格和交互图都属于结构示意，不声称展示测得的注意力权重。

## 8. 多尺度共享窗口与完整 Block 的绘法

### 8.1 三个并行尺度

当前默认版本使用三个普通窗口尺度：

| 特征网格 | 普通窗口大小 | 网格划分 | 窗口数 |
| --- | --- | --- | --- |
| 36×36 | 12×12 | 3×3 | 9 |
| 24×24 | 12×12 | 2×2 | 4 |
| 12×12 | 12×12 | 1×1 | 1 |

按行绘制时，网格、更新特征和窗口数说明分别对齐；按列绘制时，各列的操作与输出对齐。网格用 3×3、2×2、1×1 个同样大小的可见单元表达，每个单元均代表 12×12 窗口。不要把三张整网格画成一样大，从而让单个窗口的视觉大小随尺度变化。最小尺度在自身的 12×12 网格上全局关注，不能画成原 36×36 网格的全局注意力。

用括号或连线配合 `Shared within each block` 说明三个尺度共用注意力参数。这个说明必须留在功能框内，不能与底边重叠。三路增量先对齐至 36×36，再进入带权求和节点，最后接受一次空间残差相加。

注意力共享参数可用共同的绿色分组与链环图标表示；尺度融合标量另用浅奶油色节点表示，避免把两种参数误认为同一组。三个学习标量的卡片用 `Learned logits`、`Softmax` 和权重标签表达。不从输入图像、特征或热力图连入该卡片；当前代码没有图像动态生成尺度权重的路径。为减少跨图长线，可以复用同名 w1、w2、w3 输出标签，但必须在图注说明这些标签对应同一组 Softmax 输出，而非额外增加三套参数。

### 8.2 两个完整块的错位叠放

Block 1 和 Block 2 都是“类间注意力＋多尺度类内注意力”的完整块，不能分别画成一个纯类间块和一个纯类内块。

当前总览展开前方 Block 1，后方 Block 2 用偏移外框和标题表示重复结构，并注明 `2 blocks · independent weights`。仅展开一个块的细节是绘图压缩方式，不代表后方块缺少其中的操作。

| 几何项 | 当前 2000×1000 参考 |
| --- | --- |
| 前方 Block 1 | 左上角 (710, 205)，宽 780，高 395 |
| 后方 Block 2 | 左上角 (735, 150)，宽 785，高 476 |
| 两框左侧错位 | 后框向右 25 |
| 顶部错位 | 后框向上 55 |
| 右边界间隔 | 后框在右侧多露出 30 |
| 底边界间隔 | 后框在底部多露出 26 |

坐标先写横向位置，再写纵向位置；横向向右增加，纵向向下增加。尺寸可随版面调整，但必须同时露出后框的顶部、右侧和底部。不能只移动左上角却用相同右边界，也不能让两个底边和残差旁路重合。先画后块，再画白底前块，使遮挡关系自然。

同一块的三尺度共享权重，不同完整块独立学习参数。重复外框、共享括号和独立权重标签分别表达这三种关系，不能只用叠框暗示所有参数共享。

## 9. 连线、残差与引导路径

- 主信息流总体从左到右，跨阶段长线尽量走顶部或预留通道。转折优先采用简洁的水平／竖直走线。
- 文字和图片不能被连线穿过。必要交叉用小跳线或白色间隔区分；没有连接圆点的交叉不表示汇合。
- 主路径采用清晰的深灰或蓝灰实线箭头；紫色实线表示语义引导，浅绿色实线表示 FPN 空间引导。灰色虚线用于训练监督。阶段虚线是边界，不能当作数据路径。
- 箭头端点接到所对应的特征、模块或明确端口，不随意停在空白区域。新增分支先核实代码，不为了版面填充添加连接。
- 残差旁路在所属块内部预留通道，与块外框、功能框底边保持分离；加号要同时看见两路输入和一路输出。
- 路径过长时可用成对的 `to (b)` / `from (a)` 等同名端口。两端名称和张量含义一致，图注解释它们是同一特征的复用。

当前版本的结构核对要点：

| 路径 | 正确表达 |
| --- | --- |
| 图像／文本输入 | RGB 进入图像编码器；文本提示进入文本与 SAM 3 提示条件路径 |
| RemoteCLIP 引导 | 最终稠密图像特征和模板相似度生成语义引导，不使用中间层 |
| 注意力 Q/K | 条件特征与语义引导参与；窗口注意力另含 FPN 空间引导 |
| 注意力 V 与残差 | V 来自条件特征，残差只更新条件特征 |
| 语义引导复用 | 聚合内不被注意力更新；“保持同一引导”不等于训练时切断其梯度 |
| 解码输入 | 聚合特征、原始条件特征与 FPN72 进入 SDF；高分辨率 FPN 到解码器 |
| 教师路径 | 训练时原始条件特征进入同一冻结解码器的参考路径 |

模型改变时重新核对该表和图注。不能把当前三尺度、层数或权重融合方式当成不可更改的视觉规则；也不能在模型未改变时画回 score embedding 作为 V、语义状态更新、CLIP 中间层、移位窗口或旋转融合等旧结构。

## 10. 真实遥感图像、热力图与占位

当前 overview 保留五种图片位置：RGB 输入、RemoteCLIP 响应、学生响应、最终预测、教师响应。没有真实结果时使用中性棋盘格、原生图片图标及 `placeholder` 标签，不用生成式彩色图冒充模型输出。

替换真实结果时遵守：

1. 同一张图中的输入与各分支响应尽量来自同一图像、同一裁块、同一空间方向；若来自不同样例必须明确标注。
2. 为响应图写清对象：哪个类别／提示、相似度还是概率、哪个模块的特征。特征可视化须记录通道选择、聚合或降维方法。
3. 同一种数值比较使用同一色表和范围。若使用逐图归一化，需要说明，不能把它当作同一绝对尺度上的强弱比较。
4. 连续响应配连续色表和必要的色条；分割标签配离散类别色表，同一类别跨模型和跨子图颜色一致。
5. 局部放大框与放大区域一一对应；不同模型使用相同位置和放大倍数，不改变真实输出内容来美化比较。
6. 保留数据集、样本／裁块标识、提示、权重和可视化设置的记录，便于重建图。记录位置使用现有实验产物或图的配套说明，不在论文图内堆放这些实现细节。

真实图片可以带来纹理和任务感，但不能挤满所有模块。机制详图可以完全使用矢量示意，不强塞与机制无关的遥感缩略图。

## 11. 训练蒸馏栏的固定要求

训练栏置于主体下方，使用浅灰底、灰色细虚线边界和灰色文字。标题为 `Training only · frozen-reference distillation` 或含义一致的简短英文。

保留参考特征、冻结参考解码器、教师响应、学生 logits 和蒸馏损失的必要关系。教师和学生使用同一冻结解码器权重时在图注说明，不画成额外独立训练的教师网络。固定参数与计算图是否保留梯度要按实现区分，不能仅凭雪花推断。

不使用红色损失框、红色粗箭头、巨大的损失公式或发光装饰。参考编码器的冻结图标可保留低饱和蓝色；真实响应图保留其数据色表。整个训练区域在视觉上应低于主模型，但仍可读。

## 12. draw.io 源文件与导出

### 12.1 原生编辑要求

源文件位于 `src/`，最终论文图片为同名 PDF。标题、功能框、图标、张量组、窗口组、图片槽和连接器保持可编辑；相关元素合理分组，移动一个张量组时不遗留网格或标记。

绘制层级从后到前为：阶段与底板、后方 Block、前方 Block、内部功能框与图形／图片／文字、前景连接器。流程箭头应位于所有不透明底板和功能框之上；通过绕行与端点定位避开文字、图标和无关节点，不能用填充框遮盖错误线条。

存在嵌套分组时，将真实流程连接器放在独立的顶层前景图层，不只调整连接器在某个组内的顺序。Figure 3 使用 Artwork 存放底板、节点与文字，使用位于其上方的 Foreground connectors 存放流程连接器；张量网格、图标线条等装饰元素留在所属对象组内。保留 source/target 绑定与连接点，导出时同样先绘制对象、最后绘制连接器。逐条检查跨框路径、箭头尖端、跳连和交叉处，确保底板与后绘制的分组均不会盖住连线。

自定义 stencil 与嵌入图片不得依赖绘图者电脑上的临时绝对路径。

保存后同时检查 draw.io 中的源图和导出的 PDF：图层顺序、透明度、透视叠片、换行、符号和连接点均应一致。自动生成图稿也必须经过这一步，不能只因为 XML 能解析就认定绘图正确。

### 12.2 项目导出流程

以下命令从仓库根目录运行：

```bash
python3 paper/scripts/export_figures.py
```

脚本检查 `figure_manifest.json` 的源文件／PDF 哈希，只导出改变的图。安装 draw.io Desktop 并将 `drawio` 加入 PATH；也可用 `DRAWIO` 指定可执行文件。强制重新导出清单中的全部图时使用：

```bash
python3 paper/scripts/export_figures.py --force
```

编译论文：

```bash
cd paper
latexmk -xelatex -halt-on-error -file-line-error -outdir=build main.tex
```

只保留论文使用的 PDF，不额外维护 SVG。PDF 中的线条、文字和示意形状保持矢量，字体嵌入；真实图片允许为位图。PDF 与 draw.io 源图尺寸、文字和图形必须一致，不能只修改其中一个。

每次图稿修改同步维护源文件、PDF、清单、相关图注和核对记录。`figure_manifest.json` 保存文件尺寸、数量和哈希；`../notes/source_snapshot.json` 保存实际验证结果。未完成事项只放 `../notes/manuscript_status.md`，本规范不承担待办清单作用。

## 13. 绘图执行顺序

1. 阅读本规范、[当前图示定义](README.md)、[项目设计](../../DESIGN.md)及相关实现／有效配置，列清输入、输出、主路径、引导和监督。
2. 确认本次图的范围与保留内容；总览先排三个阶段，详图先确定单一机制，选择哪些细节进入图注。
3. 搭白色板块、标题留白和内部浅色功能卡片，先安排最拥挤区域和长跳连，再填充图标与张量。
4. 统一编码器图标、切片方向、网格、提示卡片、冻结／微调标记和连线语义。
5. 对内部卡片、叠框、底部标签及最右输出槽逐项检查间距，再插入真实图像或明确占位。
6. 导出 PDF，与源图对照；分别查看全图、拥挤局部及论文实际展示宽度。
7. 更新图注、清单和现有记录，编译检查后提交。需要改模型或实验数据时另按对应任务范围执行，不因绘图顺便改动。

## 14. 提交前验收表

| 检查项 | 通过条件 |
| --- | --- |
| 阶段组织 | 层级明确、标题位于白底留白；总览主路径可顺序阅读 |

| 文件与记录 | 源图、PDF、清单及实际检查记录同步；未完成项只在状态文档 |
